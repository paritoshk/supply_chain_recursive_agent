[01]System context · C4 level 1

Supplier Chief of Staff, in context. Who it talks to, and what it trusts.

A recursive supply agent for Corvane Biologics, a fictional specialty-pharma manufacturer with eight sites. It watches inventory, works a shortage end to end, and messages a planner only when a decision is above its authority. All company data is synthetic.

[01] Proactive, cheaply

A sentinel scans every material and site every 30 minutes in code. No model runs until a position breaches its reorder point.

[02] Authority

Purchases at or under $25,000 with an accepted verdict become a draft PO on their own. Everything else asks the planner on Telegram.

[03] Never

It never qualifies a supplier, changes a formulation, releases a batch or sends a real PO. Web discoveries stay discovery candidates.

[02]Containers · C4 level 2

One Vercel project, one shared core. Models call tools; tools call code.

The eve app owns channels, the schedule, the planner, the workflow and the sub-agents. Every rule, number and tool body lives in packages/core and is unit-tested; the app only wraps core tools with coreTool().

[01] Durable workflow

run_mission is an eve workflow tool. Mission setup, run records, finishing and approval are durable steps, so a redeploy or crash resumes instead of repeating a purchase.

[02] One state blob

The Store loads one JSON snapshot, runs a tool, and saves only when the tool wrote. Upstash Redis key scos:state on Vercel; .data/state.json locally.

[03] Host-compatible contracts

Every tool returns ToolOutput with ingestion_status, source and citations, so the agent can later drop into the host manufacturing platform unchanged.

[03]Recursive agent tree · components and models

Agents that spawn agents. The judge never shares a model with the doers.

The planner hands a shortage to one workflow. It fans out to three sub-agents in parallel; sourcing spawns one negotiator per approved supplier, and each negotiator bargains with a simulated supplier. An independent verifier on a different model grades the result against checks written before any work began.

[01] Definition of done first

prepareMission computes need quantity and need-by date in code, then writes five checks: covers_need, lands_in_time, qualified_only, comparable_quotes, grounded.

[02] Offers clamped in code

Each persona has a hidden SupplierProfile. clampOffer forces every reply inside its floor, list, lead time and MOQ; accept_offer stores only the supplier's last offer.

[03] Bounded recursion

At most three attempts. A loop guard stops when the next attempt's context is identical to one already tried. Scout runs once; its candidates are reused.

[05]UML sequence · fault recovery

Faults are expected. The mission still ends, honestly labelled.

Fault injection (FAULTS=persona_timeout,crusoe_429): one supplier never answers, the inference API rate-limits, and the incumbent announces a lead-time slip. The verifier sends the planner back with specific feedback, then escalates what no re-plan can fix.

[01] Backoff

crusoe.ts retries 429 and 503 with exponential backoff and full jitter, honouring Retry-After, under a process-wide concurrency limit. Crusoe limits are per model (30 RPM, or 600 with billing), so separate models per role also spread load.

[02] Timeout

A silent persona raises PersonaTimeoutError after 45 s. Sourcing continues with the other negotiators and notes the gap.

[03] Re-plan

The next attempt carries verifier_feedback. If the context is identical to a previous attempt, the loop guard stops instead of spinning.

[04] Degraded, not hung

A mission that is not accepted, or has fewer than two quotes, ends degraded. The human sees the verifier's note before approving.

[06]UML state machines

Three lifecycles, enforced in code. A cheaper quote never skips a state.

Qualification is the regulated one: the agent reads it and never moves it. RFQs move only through tools, and missions always reach a terminal state.

[B] RFQ.statusRFQ lifecycle

[01] Usable stock

Only released lots count as cover. Quarantined and rejected stock never does, and announced capacity is not available capacity.

[02] Draft only

PurchaseOrder.status is the literal draft. Sending a PO stays a human action in the ERP.

[03] Missing prices

A quote-only material keeps unit_price: null plus an rfq_reason. Nothing estimates a price.

[07]UML class diagram · packages/core/src/types.ts

The data model. Host names where they exist, new entities where they don't.

Field names for the host-compatible entities match the host manufacturing platform exactly, so the agent can move in later without a mapping layer. Everything is keyed by human-readable external_ids such as MAT-SUC-INJ, LOT-GHE-0001 and RFQ-102.
